# 핵심 개념: Python 기초 → 자료구조 → 캐시 정책

이 문서는 코드를 처음 읽는 사람을 기준으로 **정의 → 작동 원리 → 실제 코드 활용** 순서로 설명합니다.

## 1. 읽기에 필요한 Python 기초

### 1-1. 변수, 객체, 클래스, `self`

- **변수**는 객체를 가리키는 이름입니다. `a = Node("key")`는 `Node` 객체를 만들고 `a`가 참조하게 합니다.
- **클래스(class)**는 객체가 가진 데이터와 동작을 정의한 틀입니다. `class Node:`는 `prev/next/data`를 가진 노드를 만듭니다.
- **메서드(method)**는 클래스 안의 함수입니다. `node.prev = other`처럼 `.`을 통해 속성에 접근합니다.
- **`self`**는 지금 작업 중인 인스턴스를 뜻합니다. `self._size += 1`은 **현재 리스트**의 노드 개수를 하나 늘리는 문장입니다.
- **`__init__`**는 객체가 만들어질 때 호출되는 초기화 메서드입니다. `self._data = HashMap()`은 `MiniRedis`에 새로운 해시맵 하나를 붙입니다.

```python
class Box:
    def __init__(self, value):
        self.value = value

box = Box("hello")
print(box.value)  # hello
```

`linked_list.py · Node`, `mini_redis.py · MiniRedis`가 이 문법을 그대로 사용합니다.

### 1-2. `None`, 조건문, 루프, 예외

- `None`: "값이 없음"을 표현하는 특수 객체입니다. 비어 있는 버킷이나 연결되지 않은 노드에 사용합니다.
- `if ...:`: 조건을 확인하여 분기합니다. `is None`은 "정확히 None인지" 검사합니다.
- `while`: 조건이 참인 동안 반복합니다. 해시맵 체인을 탐색하고 힙의 만료 항목을 반복 정리합니다.
- `for`: 여러 바이트나 배열 항목을 순서대로 순회합니다.
- `try/except ValueError`: 정수로 바꿀 수 없는 문자열 등 예상 가능한 오류를 잡아 CLI용 오류 결과로 바꿉니다.
- `return`: 호출한 곳으로 결과를 돌려주며 해당 함수 실행을 끝냅니다. OOM 상황에서 상태를 바꾸기 **전에** `return`하는 이유입니다.

### 1-3. 리스트, 튜플, 참조와 인덱스

**Python 리스트**는 인덱스 `0, 1, 2, ...`로 항목을 찾는 배열형 컨테이너입니다. `buckets[i]`처럼 **버킷 위치를 직접 접근**하거나, 힙의 완전 이진 트리를 저장할 때만 사용합니다. `dict`/`set`처럼 키로 검색하는 역할은 맡기지 않습니다.

**튜플**은 `(expire_at, version, key)` 같은 여러 값을 한 묶음으로 저장합니다. 파이썬은 튜플을 **앞 항목부터 순서대로** 비교하므로 `(5, 1, "a") < (8, 2, "b")`가 참입니다. 힙은 이 규칙으로 가장 작은 만료시각을 찾습니다.

**참조(reference)**란 객체의 복사본이 아니라 **같은 객체를 가리키는 관계**입니다. `_Value.node`가 연결 리스트의 노드를 참조하므로 데이터 조회 후 노드를 찾기 위한 추가 순회가 필요하지 않습니다. Python에서 참조는 내부적으로 관리되므로 C처럼 메모리 주소를 직접 조작하지 않습니다.

### 1-4. UTF-8, 파싱, 시간

- `key.encode("utf-8")`: 문자를 **바이트**로 변환합니다. 영문 `a`는 보통 1바이트, 한글 `가`는 3바이트입니다. 메모리 계산은 문자 수가 아니라 바이트 수입니다.
- `shlex.split('SET a "Alice Kim"')`: `['SET', 'a', 'Alice Kim']`처럼 따옴표 안의 공백을 보존하면서 입력을 분리합니다.
- `json.dumps(value, ensure_ascii=False)`: CLI에서 큰따옴표를 붙이고 특수 문자를 이스케이프합니다. 데이터 직렬화/파일 저장을 하는 것은 아닙니다.
- `time.monotonic()`: 시간 간격을 측정하기 위한 계속 증가하는 시계입니다. TTL 만료 시각을 `현재시각 + 초`로 계산합니다.

## 2. 해시맵과 해시 충돌

**정의:** 키를 계산 가능한 배열 인덱스로 바꿔 저장하고 찾는 자료구조입니다.

**원리:** `hash_map.py · _index()`는 0에서 시작하여 키를 이루는 UTF-8 바이트마다 다음 식을 반복합니다.

```text
index = (index * 31 + byte) % bucket_count
```

그 결과로 `bucket_count`보다 작은 인덱스를 얻습니다. 예를 들어 버킷이 8개라면 ASCII `a`(97)와 `i`(105)는 모두 1번 버킷입니다. **서로 다른 키의 인덱스가 같은 상황**을 *해시 충돌*이라고 합니다.

```text
buckets[0]  → None
buckets[1]  → ("i", value_i) → ("a", value_a) → None
buckets[2]  → None
...
```

**체이닝(chaining)**은 같은 버킷에 여러 엔트리를 연결하는 충돌 해결법입니다. `get("a")`는 버킷에서 키 문자열을 순서대로 비교하며 목적지를 찾습니다. 여기서 **버킷 체인은 단방향 연결**이고, **이중 연결 리스트는 별도로 LRU 추적**에 사용합니다. 충돌 해결용으로 LRU 리스트를 재사용하는 것은 필수가 아닙니다.

**로드 팩터(load factor)**는 `저장 키 수 / 버킷 수`입니다. 예를 들어 8개 버킷에 7개 키를 저장하면 `7/8=0.875`로 제한 0.75를 넘습니다. `_resize()`는 버킷을 **16개로 확장**하고, 새 버킷 개수로 각 키를 재해싱하여 엔트리 체인을 다시 연결합니다.

**대안과 선택:** 충돌 해결에는 열린 주소 방식도 있지만, 이 미션은 체이닝을 명시하므로 `next` 포인터로 연결된 엔트리를 사용했습니다. 내장 `hash()` 대신 직접 계산한 해시 함수를 사용해 동작을 확인할 수 있습니다.

**복잡도:** 키가 고르게 분산되면 `get/put/remove`는 평균 O(1)개의 엔트리를 살펴봅니다(키의 바이트를 읽는 비용은 O(k)). 한 버킷에 전부 몰리면 O(n)이며, 버킷 확장 시 O(n) 재해싱이 한 번 필요합니다. 용량을 두 배씩 늘려 삽입의 확장 비용을 **상각**할 수 있습니다.

## 3. 이중 연결 리스트와 LRU

**정의:** 각 노드가 `data`, 이전 노드 `prev`, 다음 노드 `next`를 갖는 선형 자료구조입니다.

```text
head ⇄ [c] ⇄ [a] ⇄ [b] ⇄ tail
         최신           가장 오래됨
```

**원리:** 중간 노드 `x`를 제거하려면 양옆의 `left.next = right`, `right.prev = left`를 설정해 두 이웃을 직접 연결합니다. 노드의 위치를 **이미 알고 있다면**, 중간 노드 삭제도 O(1)입니다. 앞에 붙일 때에도 머리와 현재 첫 노드의 참조만 고치면 됩니다.

`linked_list.py`에서 `head`와 `tail`은 데이터가 없는 **가상 노드(sentinel)**입니다. 따라서 빈 리스트나 마지막 노드의 특수 상황을 처리하는 조건문이 줄어듭니다.

**LRU(Least Recently Used)**는 공간이 모자랄 때 "가장 오래 사용되지 않은 데이터"를 먼저 제거하는 정책입니다. 성공한 `SET`과 `GET`은 해당 노드를 맨 앞으로 이동시키고, 제거 시 뒤쪽의 마지막 데이터 노드를 선택합니다. 이 구현에서 `EXISTS`/`TTL`은 LRU 순서를 변경하지 않습니다.

**왜 O(1) LRU 추적인가?** 단순 배열만으로는 특정 키의 위치를 찾는 데 O(n)이 걸릴 수 있습니다. 하지만 해시맵의 값에 **연결 리스트 노드의 참조**가 보관됩니다. 키 조회 평균 O(1) 후 노드 이동 O(1)이므로, 해시 분포와 키 길이가 일반적이라면 LRU 갱신도 평균 O(1)입니다.

**대안과 선택:** 각 키의 최근 사용 시각을 저장하고 삭제할 때 전체를 검색하는 구현은 간단하지만, 제거 대상 탐색에 O(n)이 듭니다. 연결 리스트는 노드 참조를 더 저장하는 대신 뒤쪽에서 즉시 제거할 수 있습니다.

## 4. 최소 힙과 TTL

**정의:** 모든 부모의 값이 자식의 값 이하인 **완전 이진 트리**입니다. 완전 이진 트리는 마지막 층을 제외한 층이 모두 채워지고 마지막 층은 왼쪽부터 채워집니다. 따라서 인덱스로 부모와 자식을 계산할 수 있어 **리스트 하나로 표현**할 수 있습니다.

```text
리스트:   [2, 5, 7, 9, 6]
인덱스:    0  1  2  3  4

              2 (0)
             /     \
          5 (1)   7 (2)
          /   \
       9 (3) 6 (4)
```

**원리:** `min_heap.py`의 인덱스 `i`에 대해 부모는 `(i-1)//2`, 왼쪽 자식은 `2*i+1`, 오른쪽은 `2*i+2`입니다.

- `push`: 리스트 끝에 추가하고 부모보다 작으면 위로 교환합니다(`_heapify_up`).
- `pop`: 루트(최솟값)를 꺼내고 마지막 값을 루트로 옮긴 뒤 작은 자식과 아래로 교환합니다(`_heapify_down`).
- `peek`: 루트만 확인하므로 정렬이나 전체 순회가 불필요합니다.

**TTL(Time To Live)**은 데이터가 유효한 기간입니다. "가장 먼저 만료되는 항목"을 확인해야 하므로 최소 힙이 적합합니다. 각 `EXPIRE` 호출 때 `(expire_at, version, key)` 예약을 추가하고, 명령을 처리하기 전에 루트 예약이 이미 만료되었는지 검사합니다.

**버전과 지연 삭제:** 같은 키의 TTL을 덮어쓰거나 키를 삭제 후 다시 만들 수도 있습니다. 예전 예약을 힙에서 즉시 찾아 제거하는 대신, 현재 레코드의 **버전과 만료시각**을 비교해 옛 예약을 무시합니다. 이 전략이 *lazy deletion(지연 삭제)*입니다. 힙의 임의 위치를 즉시 지우려면 위치를 추가로 추적해야 하므로 로직이 복잡해집니다.

**복잡도:** `push/pop`은 O(log h), `peek`은 O(1)입니다(`h`: 힙 예약 개수). 만료 정리는 도래한 예약만큼 반복합니다. 예전 예약은 데이터가 이미 삭제·갱신되었어도 최신 버전과 일치하지 않으므로 새 값을 삭제하지 않습니다.

## 5. 세 구조를 결합해 캐시를 구현하기

`mini_redis.py · _set, _get, _expire, _purge_expired, _delete`는 세 자료구조를 함께 사용합니다.

| 작업 | 해시맵 | 이중 연결 리스트 | 최소 힙 |
| --- | --- | --- | --- |
| 새 `SET` | 키→값/노드 저장 | 앞에 노드 생성 | 없음 |
| 기존 `SET` | 값 교체·TTL 초기화 | 맨 앞으로 이동 | 이전 만료 예약 무효화 |
| 성공 `GET` | 값 조회 | 맨 앞으로 이동 | 명령 시작에 만료 정리 |
| `EXPIRE` | 레코드에 시각·버전 저장 | 변경 없음 | 만료 예약 삽입 |
| `DEL` | 키 제거 | 노드 제거 | 예약 무효화 |
| TTL 만료 | 키 제거 | 노드 제거 | 가장 빠른 예약을 꺼냄 |
| LRU 제거 | 키 제거 | 맨 뒤 노드 제거 | 예약 무효화 |

**메모리 계산에서의 주의점:** `len("가") == 1`이지만 `len("가".encode("utf-8")) == 3`입니다. `used_memory`는 살아 있는 키/값의 UTF-8 바이트만 합산합니다. 버킷·노드·힙의 Python 객체 메모리는 제외합니다.

**실제 시간 복잡도:** 해시맵 평균 O(1)과 LRU 노드 이동 O(1)은 **만료 정리, 키 길이, 여러 항목 삭제, 재해싱을 제외한 핵심 동작**의 비용입니다. 한 명령의 전체 시간은 도래한 만료 예약 개수와 메모리 초과로 제거되는 키 개수에 따라서 늘어날 수 있습니다.
